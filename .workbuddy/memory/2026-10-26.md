### 核心问题：提交历史两套写法混用
25 条提交里只有 2 条符合 Conventional Commits，其余是「修复xxx：说明」/「前端：说明」。
后果：没法自动生成 changelog、没法按类型筛提交、没法推导语义化版本。
多人协作会把这个缺陷放大到不可读。

### 落地内容

**1. `.gitattributes`**
`* text=auto eol=lf` + 逐类型声明。为什么强制全平台 LF：
shell 脚本带 CRLF 在容器里报 `bash: $'\r': command not found`，极难排查。
另外用 linguist 规则把 `nlohmann/json.hpp`（1.5 万行第三方单头库）标 vendored，
否则 C++ 语言统计被淹没；lock 文件标 generated 折叠 diff。

**2. `scripts/check_commit_msg.py`（单一实现，两处调用）**
校验 Conventional Commits。设计要点：
- 支持中文 subject（这个项目主体是中文，不能照搬英文规范）
- 头部限 100 **字符**（不是字节），中文按 1 计
- 标了 `!` 但没写 `BREAKING CHANGE:` 脚注 → warning（升级者不知道要改什么）
- 首行与正文之间没空行 → error（`git log --oneline` 会显示成一大段）
- 豁免 Merge/Revert/fixup!/squash! 等自动生成格式
- 三种模式：`--file`（commit-msg 钩子）、`-m`（单条）、`--range`（CI 区间）
- 区间模式用 compact 输出，详细指引只在结尾给一次（否则每条刷三行太吵）

**3. `CONTRIBUTING.md`**
核心不是列流程，而是讲清这个项目的**风险模型**——为什么这里规矩比别人严：
普通项目改错会报错；这里改错可能让结论**静默**变（附 `shift(1)→shift(2)`
让收益从 18% 变 34% 的例子）。
四档风险分级 L0 文档 / L1 业务层 / L2 策略表达 / L3 计算核心，
L3 要求等价性 + 不变量 + PR 说明对历史结论的影响。
另外强调一条经验：**「改门槛、结果不变」的测试比「结果等于某数字」的测试更有价值**。

**4. `.github/` 四个配置**
- `PULL_REQUEST_TEMPLATE.md`：验证证据是评审主要依据；C++ 改动必须勾"已确认真的用上新产物"
- `ISSUE_TEMPLATE/{bug_report,feature_request,config}.yml`：bug 模板先给"现象→可能原因"对照表；
  置 `blank_issues_enabled: false` 引导走模板
- `CODEOWNERS`：按风险分派（cpp/execution/core/metrics/risk/engine/gateway 全部单列）
- `dependabot.yml`：**关键决策——pandas/numpy 禁止自动升 minor**。
  理由：CI 只验证"不崩"，不验证"回测数值没变"。这类升级必须人工比对结论。

**5. `docs/COLLABORATION.md`**
记那些**文件表达不了、只能网页/API 配**的东西：分支保护 12 项设置、
required checks 名单、合并策略（只许 squash + rebase）、标签体系、安全开关、权限分级。
附 curl 脚本（环境无 gh CLI）和"新接手一个人"的 7 步清单。
最后一步"确认自己不能直推 main"最容易漏——有 Admin 权限的人分支保护对他无效。

**6. CI 强化**
- `concurrency` 取消陈旧运行（PR 反复推 10 次只跑最后一次，省额度）
- 显式 `permissions: contents: read`，images job 单独要 `packages: write`
- 拆成 4 个并行 job：commit-messages / backend / frontend / gateway（原来 backend+frontend 串行）
- 新增 `commit-messages` job，复用同一脚本
- 修正一个真实隐患：PR 事件默认 checkout **合并提交**，`origin/main..HEAD` 会算进
  不该算的提交 → 改为 checkout `pull_request.head.sha` + 用 `base.sha` 算区间
- images job 加 `cache-from/to: type=gha`，多人频繁合并时省构建时间
