## 市场能力三维建模（回转 / 交收 / 做空）

**背景**：用户指出「有些股市不能做空，有些可以 T+0，有些只能 T+1」，要求区分。审查发现三个真实缺口：
1. 前端根本没有 `direction` 选择器（`BacktestRequest` TS 类型缺字段）——所以用户「只能买/卖」；
2. `can_short` 硬编码仅 CRYPTO（`EngineConfig.validate` 判断 `market != "CRYPTO"`），美股/港股实际可空；
3. `t_plus_1` 单个布尔撑不起港股的「T+0 回转 + T+2 交收」，场内 ETF 被一刀切当 T+1。

**方案**：`BoardRules` 拆三维，新增字段
- `settlement_days: int = 1`（交收 T+N，信息字段，不参与撮合）
- `short_restricted: bool = False`（可空但受名单约束）
- `short_note: str = ""`（资格说明）
- 派生 `trade_mode` / `trade_mode_label` / `settlement_label` / `short_label`，`capabilities()` 作为 API 唯一出口
- 新增 `market_rules(market)` 市场级入口（`_MARKET_BOARD` 映射）

**矩阵**：CN 主板/创业板/科创板/北交所 T+1 不可空；场内股票 ETF T+1；场内债券/货币/跨境/黄金 ETF（511/513/518）T+0；美股 T+0 回转 T+1 交收可空；港股 T+0 回转 T+2 交收仅指定名单可空；CRYPTO T+0 无交收可空；场外基金不可空。

**同步点**：
- `cpp/core.cpp::rules_for`：US/HK `can_short=true`，ETF T+0 前缀（必须先于通用 `51` 判断）
- `EngineConfig.validate` 改走 `market_rules(...).can_short`
- `MarketOut` / `InstrumentOut` 加 8 个能力字段，`/market/markets`、`/market/instrument` 填充
- 前端：`types.ts` 加 `direction` + 能力字段；`Backtest`/`Paper`/`Instrument` 三处入口加方向选择器（市场不支持则 disabled 并自动回落 long）；`Instrument` 规则区拆「当日回转 / 交收周期 / 做空」
- `utils/format.ts` 加 `marketCodeOf(symbol)`

**测试**：505 → 514。新增能力矩阵、`market_rules`、ETF T+0 vs T+1、capabilities 字段对齐、API 能力字段、美股/港股账本层负持仓、美股/港股 native 空头首笔为卖出。

**验证**：`ruff check/format`（从仓库根目录跑）、pytest 514 passed、`tsc --noEmit`、ESLint、Prettier 全绿。`vite build` 因沙箱 Wasm 内存不足失败（非代码问题）。

**教训**：Edit 工具多次把 `def foo():\n` 的换行吃掉导致语法错误——old_string 带结尾换行时要小心，改完必须读回确认。

## 本地起服务时暴露的两个 C++ 漏同步（已修）

用真实接口跑美股做空回测时发现，Python 侧修好的两处 C++ 没跟上：

1. `cpp/engine.cpp` 持仓序列化 `unrealized_pct` 分母少了 `std::abs()`：空头 `cost_value` 为负，
   亏损被显示成 **+69% 盈利**（Python 的 `Position.unrealized_pct` 已用 abs 分母）。
2. 同一处缺 `direction` 字段 → 前端持仓表「方向」列把空单显示成多单。

修法：`pos.is_short() ? "short" : "long"` + `(mv - cost_value) / std::abs(cost_value)`，
并新增 `test_native_short_position_fields_are_consistent`（断言 direction 与 pct 符号一致）。

**通用教训**：C++ 与 Python 的「等价性」不能只覆盖成交与权益，**持仓字典的字段集与派生指标**
也要逐字段比对——这次是 `unrealized_pct` 与 `direction` 两处静默分歧。

## 行情/排行榜「不更新」的排查结论（20:30）

现象：页面排行榜空白、标的报价 0；接口始终 200，note 写「数据源可能限流或休市」。

根因：数据源被切成 `synthetic`。实时快照与排行榜都走 **HTTP 直连**（腾讯/东财/新浪/交易所 REST），
本来不碰 akshare，也不碰 py_mini_racer；只有 `daily` 与 `_search_cn` 才惰性 import akshare。
所以「行情/排行榜」与「回测日线」用的是不同代码路径，不该用同一个开关一起降级。

修复：`QUANT_DATA_PROVIDER=akshare`；沙箱内 OKX/Binance 不通、**Gate 通**，故 `QUANT_CRYPTO_EXCHANGE=gate`。

顺带修可观测性：`MarketDataService.ranking` 拆出 `ranking_ex()` 返回 `(items, note)`，
把空榜原因分成「数据源不支持（改配置即可）」「取数报错（自动重试）」「源返回空（休市/限流）」。
此前三种都退化成同一句「可能限流或休市」，正是这次把配置错误伪装成休市的直接原因。

## 前端「按钮不生效」的三个真问题（20:45）

1. **Service Worker + 固定文件名 = 永远跑第一版前端**（本次主因）。
   `sw.js` 对 `/assets/*` 是 **cache-first**（按完整 URL 存），而本地预览包用 esbuild
   输出固定名 `main.js`（不带内容哈希）→ 首次访问后浏览器永远命中旧缓存，
   后端怎么改、怎么刷新页面都看不到新代码。Vite 正式构建默认 `main-[hash].js` 所以生产不受影响，
   是我手工打包引入的坑。
   修：打包改用 `--entry-names=main-[hash]`，index.html 动态引用实际文件名；
   `sw.js` 的 `CACHE` 升到 `quant-shell-v4` 清掉旧条目。
   **教训**：任何 cache-first 的静态资源都不能用固定文件名。

2. **`rawFetch` 没有超时**。请求一旦挂住（数据源慢、代理半通），`finally` 永不执行，
   `loading` 状态卡在 true，`Button disabled={disabled || loading}` 就永久灰着——
   用户看到的就是「点了没反应」。`usePolling` 的 `inFlight` 还会因此永久停轮询。
   修：`rawFetch` 统一加 `AbortController` 超时（默认 30s），超时抛 `ApiError('请求超时…')`；
   慢接口单独放宽（bars 60s、refresh 120s），快接口收紧（quote/indices 12s）。
   `request()` 的 catch 放行已是 ApiError 的异常，避免把「超时」改写成「无法连接服务器」。

3. **事件处理器异常对用户完全不可见**。没有 ErrorBoundary（渲染抛错→白屏），
   也没有 window error/unhandledrejection 监听（onClick 抛错只在 console 里有）。
   修：新增 `components/ErrorBoundary.tsx` 显示报错+重试；App 里把全局错误转 toast，
   并过滤 `AbortError`（切页/轮询主动取消不是错误）。
   另：自选为空时点「立即刷新」直接 return，现在给 toast 说明原因；缓存表「刷新」补 loading 态。

## 在 4GB 沙箱里跑前端冒烟的可行做法（可复用）

- `npx vite dev/build` 与任何 `undici` 请求都会因 `WebAssembly.instantiate` 无法分配而崩
  （Node 22 的 llhttp 是 wasm）。**绕开办法：用 `node:http` 自己实现 fetch**。
- jsdom 可以跑打包产物：先注入 `window/document/localStorage` 等全局，
  stub `matchMedia`/`ResizeObserver`/`WebSocket`，再 `await import(bundle)`。
  注意别覆盖 `globalThis.performance`（undici 依赖 `markResourceTiming`）。
- 断言页面正常与否看 `#root` 的 `textContent`；echarts 在 jsdom 里因 `getContext` 返回 null
  必定抛 `clearRect`，属于环境限制，验证按钮时把 chart 卡片 `visible:false` 跳过。
- stub 接口必须返回 **Response 形状**（`{ok,status,json,text,headers}`），直接返回裸 JSON 会让
  `request()` 判定失败，表现成「登录态没建立」。
