## 新闻因子打分器重写（用户反馈「影响很大的新闻，因子却给得很离谱」）

### 旧实现的问题（用实库 172 条数据量化）

旧 `classifier.py` 是纯关键词计数：`sentiment = (0.25×正面词数 − 0.30×负面词数) / max(1, 正+负)`。
结构性缺陷三条：

1. **没有量级维度**。「降息 50bp」与「上涨」两字同分 +0.25；「禁止提现 30 亿美元」与「禁止」同分 −0.30。
   用户说的"影响非常大但因子有问题"，本质是这套公式里根本没有"影响多大"这个字段。
2. **词表几乎只有中文**。实库 172 条里 105 条英文（62%），drops/tumbles/plunges/slumps 全不在表里
   → **115 条（68%）的 sentiment 恰好为 0**。BTC 跌 5% 那条给的是 0.00。
3. **confidence 算的是"命中几种词"**（`0.35 + 0.1×hits`）。于是「提醒：日内请重点关注」这种
   日历条目拿到全库最高的 0.95，在 `compute_factor` 里权重最大 —— **信息量最少的新闻影响力最大**。

另有两处语义错误：`policy_risk` 与方向脱钩（「SEC 批准 ETF」「美联储降息」因含政策词被判 0.55~0.65
的政策风险，利好消息被当风险源）；否定不识别（「不会立即影响关税协议」→ policy_risk 0.55）。
`event_type` 是固定顺序 first-match，「基金行业调查中被逮捕」归成 etf、「华尔街见闻早餐」归成 security。

### 新实现（三层）

1. **强度词表**：每个词带量级 1.0/0.8/0.55/0.3，同极性多词按 0.45 递减叠加（避免同义反复刷分）。
   英文支持 `*` 后缀通配前缀匹配（`investigat*`），非通配词走词边界正则——
   **`_find_pos` 必须也用词边界**，否则 `drop` 会命中 `drops` 导致同一新闻重复计分（踩过）。
2. **幅度放大**：抽 `%` / `基点` / 金额，换算系数后**取平方根**并入（跌 20% 不该是跌 1% 的 20 倍）。
   加 `_DAMPENERS`（小幅/轻微/slightly）做 0.6 折扣，「小幅回调」与「回调」不再同分。
3. **否定做方向翻转**，不是归零：
   - 正面词被否定 → 计入负面 ×0.75（「美联储不会降息」是利空）
   - 负面词被否定 → 计入正面 ×0.35（「央行未加息」轻微利好）
   - 后置否定单独处理：中文常是「关税不会影响…」，否定在词**后面**，前置窗口抓不到 → `_POST_NEGATION`
   - **双重否定**「不能排除/不排除/无法排除」必须放进 `_FALSE_NEGATION`，否则
     「不能排除美股大跌」会被翻转成 +0.25（实库 23204 条踩到）
4. `policy_risk` 看政策动作方向：打压性（禁止/处罚/调查/制裁）0.72 起；支持性（批准/降息/合法化）≤0.30；
   一般提及 0.35~0.60；强否认（否认/辟谣 + 被打压的政策动作）→ risk×0.35 且给 +0.25（利空落空是利好）。
5. `confidence` 改为**文本可判断程度**：有数字 +0.18、有明确主体 +0.12、长度 +0.05、
   汇编/日历类（早餐/盘点/重点关注/what happened）-0.40。
6. `event_type` 改为按命中数打分取最大，不再固定顺序。
7. `_MILESTONE_BONUSES`：etf+批准 +0.45、现货+etf +0.15，把分水岭事件抬到应有的量级。

### 关键取舍

- **不加 DB 列**。`create_all` 只建新表，给已有表加列要写迁移；把量级并入 `sentiment` 语义即可，
  C++ / 策略 / 前端结构零改动。`compute_factor` 的聚合逻辑不用动。
- `surge*/soar*/rally` 从 0.8 **降到 0.55**：`hacks surge` 里 surge 被当利好，与 hacks 抵消成 0。
  降权后 -0.22，方向正确。

## 带新闻的策略回测排查（news_dual_ma，多空各跑一遍）

用容器内直连引擎的方式跑了 A 股日线 / 加密日线 / 加密 15m·60m，做多与做空都覆盖。
发现的真问题与修复：

1. **PIT 时钟用错**：`factors._item_dt` 取 `effective_at`（入库时间）。补录的 177 条新闻
   effective_at 全被盖成 11-05 14:14，于是任何历史 bar 都看不到 → A股日线 202/202 根 bar
   新闻覆盖 0，"带新闻的策略"数值上与 dual_ma 完全一致（0.0166 / 4 笔）。改为
   `min(published_at, effective_at)`；仓储 `for_symbols` 区间过滤同步放宽成 OR，否则
   SQL 阶段就把补录行滤掉。
2. **news_window=1d 直接 KeyError**：`NEWS_FIELDS` 只有 1h 四个字段 + 1d 两个字段，而
   `build_spec` 会拼出四个 1d 字段名。改为 metric × window 笛卡尔积生成
   （`news_field()` 统一命名），并修 15m/4h 被静默映射成 `_1d` 的问题。
3. **覆盖率不可见**：引擎新增 `_news_extras` / `_report_news_coverage`，把
   "覆盖 N/M 根 bar（x%）"写进 result.logs；0 覆盖升级为 warning 并提示策略等价纯技术信号；
   日线 + 1h 窗口额外提示改 1d。

实测（修复后）：BTC 15m 11-05 新闻活跃窗口 85/98 bar 有新闻，做多 6→5（必须有新闻）→4
（情绪>=-0.1）→3（情绪>=0.2），做空 3→2，证明门槛真的生效。A股全年 1d 窗口覆盖 4/202（2%），
日志明确提示"影响可忽略"。

顺带发现（未修，待定）：A股 600519 一手 14.5 万 > 默认 10 万初始资金，buy_hold 静默 0 成交；
做空方向没有"利空门槛"（min_sentiment 是下界，无法表达"只在利空时开空"）。
