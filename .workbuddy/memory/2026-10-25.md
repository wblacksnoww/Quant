### 现状盘点（重要，纠正了上一轮的误判）

### 真实缺口只有三处
1. **benchmark**：`engine.cpp` 里搜 "benchmark" 零命中 →

3. **纸盘/实盘 step 调度**：信号已走 C++，但逐 bar 推进在 Python。
   用户认可这一项**保留 Python**（网络 IO/线程/重连不该塞进 C++）。

- 缺的不是 C++ 能力，是**数据源**（AkShare 只有日线/分钟，无历史 tick）。

### 本轮新抓到的两个真实 bug（都在 tick.py）
1. **时间轴格式不兼容**：`SyntheticTickProvider.fetch` 硬读 `df["date"]`，
   但 `MarketDataService.bars()` / `minute_bars()` 把时间放在 **DatetimeIndex**，

- 另加守门测试 `test_flat_price_returns_only_fees`：常数价格下收益必须只反映手续费，

### 关键发现：Python 算子这条路原本**跑不通**
`quant/strategy/indicators.py` 里已有 Python 指标函数，但：
- spec 校验白名单 `_INDICATORS` 是静态的 → 新指标名直接 `_fail`
- C++ `indicator_kind()` 是 if 链，编译期固定
所以"用 Python 写算子"写在代码里也没有入口。**真正缺的是机制，不是函数。**

### 实现：`backend/quant/strategy/operators.py`
核心洞察：**C++ 主循环一行都不用改**。
`Columns::at()` 本来就从 extras 按列名取值、取不到返回 NaN ——
新闻字段走的就是这条路。算子只是复用这个机制：
```
@register_operator("zscore", period=("int", 20))
def _zscore(frame, period=20): ...
spec: {"kind":"field","field":"op:zscore(period=20)"}
→ 引擎全序列预计算成 extras 列 → C++ 照常求值
```
`custom.py` 的 `parse_operand` 加 `op:` 前缀分支，绕过静态白名单。

### 三条纪律（写进模块文档 + 测试锁定）
1. **必须因果**：`assert_causal()` 用"截断输入、比前缀输出"抽查。
   实测能抓出 `shift(-1)` 和全样本标准化（`(x-x.mean())/x.std()`）。
2. **warmup 返回 NaN 而非 0**：C++ 里 `NaN>x` 为 false（条件不成立），
   而 `0>x` 可能为 true（假信号）。这是最容易踩的坑。
3. **结果必须标注研究通道**：进生产要在 `cpp/indicators.cpp` 重写 + 过等价性。

内置范本算子：`zscore` / `vol_ratio` / `gap`。

### 又修掉三个可用性缺口（都是"日志里有、用户看不到"）
1. 新闻缺失告警只写 `log.warning`，没进 `result.logs` → 用户在 API/界面
   完全看不到"策略已退化"。
2. `_run_native` 用 `result.logs = raw_result["logs"]` **整体覆盖**，
   把调用前记的告警冲掉了 → 改为追加。
3. 算子未注册时只有 logger 告警，回测零成交却无任何用户可见提示
   → 新增 `resolve_operator()` 预体检，汇总成一条 error 级日志，点名算子。
   顺带发现：`test_unregistered_operator_...` 原断言只查 "算子" 二字，

### 一个必须记住的结构性事实
`custom_rule` **没有 Python 信号腿**：`CustomRuleStrategy.__init__` 要求
`HAS_NATIVE`，否则直接 RuntimeError。因为信号编译/求值只在 C++ 实现，
Python 侧只有语法校验。
→ 所以"拼装策略+新闻字段的两条腿逐笔比对"**做不到**，测试里没有假装能做，
而是把这条事实本身写成测试（`TestCustomRuleHasNoPythonLeg`）。
