# 实盘交易接入（LIVE_TRADING）

> **风险声明**：实盘功能会让程序直接向交易所/券商发送真实委托。本文档只说明如何
> 正确配置与验证，不构成投资建议。默认状态是**关闭**的，开启与真实资金下单都需要
> 显式确认。请先用测试网完整验证策略，再考虑真实资金。

## 1. 架构与安全边界

```
Strategy ──submit──> RiskManager（前置风控）
                        │
                        ▼
                  LiveBroker  ──place/cancel──>  BrokerAdapter  ──> 交易所 / 券商
                        ▲                             │
                        │        sync() 回报           │
                        └── 增量记账 <── 累计成交/状态 ──┘
                        │
                  Account（本地镜像）──reconcile()──> 交易所资金/持仓
```

- **不本地撮合**：成交只来自交易所回报（`LiveBroker.on_bar` 不产生成交）。
- **累计口径幂等**：适配器返回累计成交量/均价/费用，`LiveBroker` 计算增量，
  重复 `sync()` 不会重复记账。
- **对账不自动改账**：`reconcile()` 只报告本地镜像与交易所的差异并写日志，
  避免"漏成交被余额覆盖"式的静默错误。
- **停止即撤单**：`POST /api/live/stop` → `session.finish()` → `broker.cancel_all()`，
  逐单向交易所撤单（DAY 单在跨日时也会撤）。

### 三道闸门（缺一不可）

| # | 闸门 | 位置 |
|---|------|------|
| 1 | 服务端 `QUANT_ENABLE_LIVE_TRADING=true`（默认 false） | `config.py` / `routers/live.py` |
| 2 | 适配器 `sandbox=True`（默认）；关闭时必须 `confirm_live=true` | `LiveStartRequest` |
| 3 | 凭据必须属于当前用户且 `kind=broker`，每次启动写审计 | `credentials` 表 / 审计链 |

另外：同一**凭证**同时只允许一个实盘会话（防止两套策略争抢同一笔资金）；不同凭证可并行。

## 2. 虚拟货币实盘（ccxt）

支持所有 ccxt 交易所的**现货**（`okx` / `binance` / `gate` …），合约不在范围内。

### 2.1 准备

1. 在目标交易所开启 API，权限只勾**交易**（不要勾提现），建议绑定 IP 白名单；
2. 若交易所支持测试网，先在测试网创建一套 Key；
3. 本机网络：国外交易所直连不畅时设置代理（实测 OKX 直连失败、走 xray 正常）：

```dotenv
QUANT_CRYPTO_EXCHANGE=okx
# 宿主机直接运行：
QUANT_CRYPTO_PROXY=http://127.0.0.1:10808
# Docker 部署时 127.0.0.1 是容器自身，必须走宿主网关（compose 已加 host-gateway 映射）：
#QUANT_CRYPTO_PROXY=http://host.docker.internal:10808
```

4. 安装依赖：`pip install ccxt`（已随主依赖安装；镜像重建后自动包含）。

### 2.2 创建凭据

「设置 → 凭据 → 新建」，`kind` 选 **broker**，payload 填：

```json
{"exchange": "okx", "api_key": "…", "secret": "…", "password": "…(如有)"}
```

凭据用 AES-256-GCM 加密存储（AAD 绑定用户与名称），列表接口不返回明文；
`reveal` 仅管理员可调用且写审计。

### 2.3 开启闸门并启动

```dotenv
QUANT_ENABLE_LIVE_TRADING=true
```

重启服务后进入「实盘」页：

1. 策略选一个（先用 `buy_hold` 验证链路）；
2. 通道 `ccxt`，标的 `CRYPTO:BTC/USDT`；
3. 凭据选刚创建的 broker 凭据；
4. **保持「测试网 / 模拟账户」勾选**，启动；
5. 观察「会话状态 → 成交」是否出现回报，`挂单/成交` 与交易所页面一致；
6. 停止会话，确认交易所侧挂单已撤销。

### 2.4 切到真实资金

取消「测试网」勾选 → 页面出现红色风险提示 → 勾选「我确认使用真实资金」→ 启动。
建议先用极小金额（例如 10 USDT）跑一轮完整买卖，再放大。

> 交易所的最小下单量各不相同（OKX BTC/USDT 最小 0.00001 BTC）。
> 数量由策略决定，系统只做资金/整手校验，最小名义金额由交易所拒单，会以
> `REJECTED` + 交易所原因出现在订单列表里。

## 3. A 股实盘（miniQMT）

### 3.1 前提条件（缺一不可）

1. **Windows 本机**安装券商 QMT 终端（miniQMT 版），并开启极简模式；
2. 券商已为你开通**程序化交易权限**（A 股程序化交易需向券商报备，遵守交易所规定）；
3. 已安装 `xtquant` Python 包（随 QMT 终端提供）；
4. 本服务能访问 QMT 的 `userdata_mini` 目录。

> **重要**：开发/CI 环境（Linux/Docker）没有 QMT，`connect()` 会明确报错。
> 本仓库只保证接口与状态映射正确，**真实下单必须在你自己的 Windows 机器上联调**。
> 系统不绕过券商风控：所有委托最终都要经过 QMT 与券商端的合规校验。

### 3.2 创建凭据

```json
{"path": "C:/QMT/userdata_mini", "account_id": "你的资金账号", "session_id": 123456}
```

### 3.3 启动

通道选 `miniqmt`，标的填 `CN:600519`（单一市场），`sandbox` 对应 QMT 模拟账户。
建议先用 QMT 模拟账户跑通，再切真实账户。

### 3.4 费用与对账

QMT 的委托查询不返回逐笔费用，`sync()` 里费用按 0 记，**账户盈亏以券商日终账单为准**。
对账（每 `reconcile_interval` 秒）会把本地镜像与 QMT 资金/持仓的差异写进日志与
WS 事件（`run.log`）。

## 4. 中途切换策略

实盘运行的**下一轮轮询**会切换到新策略（无需停止会话）：

1. 实盘页运行中会出现「切换策略（下一轮生效）」；
2. 选择新策略与参数，默认勾选「撤销旧策略的未成交挂单」；
3. 确认后返回 `from/to`，`状态 → 策略` 在下一轮更新。

语义（务必理解）：

- **持仓与资金保留**：新策略接管当前账户，从现有仓位上继续决策；
- **旧挂单默认撤销**：下单会真实发往交易所（逐单 `cancel`）；不想撤可以取消勾选；
- **不继承策略状态**：新策略是全新实例（自己的 `on_start` 重新初始化），
  旧策略的冷却期/计数器不会带过去；
- **切换是原子的**：发生在两轮行情处理之间，不会在 `on_bars` 执行到一半时替换；
- **历史记录**：`runs` 表保留启动时的策略；切换动作写入 `run.log` 与审计日志
  （`live.switch_strategy`），当前策略可在 `GET /api/live/state` 的 `strategy_id` 查看。

> 如果只是调参数（同一策略），同样走切换接口：选同一个策略、改参数即可。
> 不建议在切换的同时手工撤单/改单，容易与程序的下单指令交错。

## 5. 运行与运维

| 操作 | 接口 | 说明 |
|------|------|------|
| 列出通道 | `GET /api/live/adapters` | 前端下拉用 |
| 启动 | `POST /api/live/start` | 202 + run_id；审计 `live.start` |
| 状态 | `GET /api/live/state` | 现金/持仓/挂单/成交/对账时间 |
| 停止 | `POST /api/live/stop` | 逐单撤单；审计 `live.stop` |
| 历史 | `GET /api/live/runs` | `runs.kind="live"` |

实盘会话的事件与纸盘一样经 `EventBus → EventHub → /ws` 按用户定向推送，
前端「实盘」页按 `run_id` 过滤。

### 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 403 实盘功能未开启 | 闸门 1 | 设置 `QUANT_ENABLE_LIVE_TRADING=true` 并重启 |
| 422 需要 confirm_live | 闸门 2 | 勾选确认，或保持测试网 |
| 404 凭据不存在 | 凭据不属于当前用户 | 用本人账号创建 `kind=broker` 凭据 |
| `connect` 报 API Key | 凭据 payload 缺字段 | 检查 `api_key/secret` |
| OKX 拉取超时 | 网络 | 设 `QUANT_CRYPTO_PROXY` |
| miniQMT 报未安装 xtquant | Linux/Docker 环境 | 只能在 Windows + QMT 机器上运行 |
| 订单一直被拒 | 资金不足/整手/交易所最小量 | 看订单 `reason`（含交易所原因） |
| 对账差异 | 漏回报/手工交易/费用口径 | 看 `run.log`；必要时以交易所为准手工核对 |

## 6. 已知边界（明说）

- **现货 only**：合约、杠杆、期权未实现。
- **无盘中分钟线撮合**：实盘每轮用最新价驱动策略，策略看到的是"当前价"，
  不是完整 OHLC；限价单存活由交易所决定。
- **A 股 T+1**：由 `BoardRules.t_plus_1` 驱动本地可卖校验；实际交收以券商为准。
- **无移动止损/条件单**：只支持下单与撤单；条件单需在策略里轮询判断。
- **单进程**：`LiveManager` 是进程内状态；多副本部署时同一账号可能在不同实例
  各开一个会话——生产请用单实例或外部锁。
- **实盘数据不参与回测**：`runs` 记录只用于复盘展示。
